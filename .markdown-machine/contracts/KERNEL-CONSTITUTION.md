# Kernel Constitution

The universal kernel is capability-neutral. It owns:

- positive authority/currentness;
- bootstrap trust;
- human intent provenance;
- natural-language human control/session-boundary interpretation;
- Task/Attempt identity;
- capability onboarding framework;
- LifecycleGraph revisions;
- Run Horizon;
- Inbox/change control;
- convergence;
- context routing/representation;
- skills routing;
- Worker/review independence;
- enforcement requirements;
- resources/effects;
- external currentness;
- repository persistence/closeout synchronization;
- execution agnosticism and project-specific strategy selection;
- STOP/recovery;
- handoff projections;
- kernel/capability migration.

Humans communicate control intent in ordinary language under `22-HUMAN-CONTROL.md`; reserved machine tokens are internal and are not a required user command vocabulary.

## Migration continuity floor

Beginning with the v0.5.0 release line, governed kernel/capability migration is a permanent universal-kernel capability and a mandatory successor-release compatibility surface. A later Markdown Machine release MUST NOT make an otherwise valid project lose its project-local lawful migration mechanism merely by removing `KERNEL_MIGRATE`, omitting required migration/currentness/history semantics from compiled closure, declaring migration unsupported by default, or requiring re-bootstrap, a second Genesis, or project-history reset as the ordinary way to adopt a successor.

This is a migration-mechanism continuity guarantee, not a guarantee that every candidate transformation is semantically compatible. Exact candidate migration may still `BLOCK` or `REJECT` for a real incompatibility, unresolved human-owned distinction, barrier, failed preservation proof, or other existing fail-closed condition. A successor release remains acceptable only if the project can evaluate that outcome through the governed migration path rather than being stranded because migration support itself disappeared.

Capability definitions may tighten these rules but may never weaken them.

Capability definitions govern domain outcomes and constraints, not preferred implementation technologies. All capabilities inherit the execution-agnostic constitution in `21-EXECUTION-AGNOSTICISM.md`.

Software Product Freeze is capability-specific, not universal.
