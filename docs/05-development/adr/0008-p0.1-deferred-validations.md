# ADR-0008 -- P0.1 defers offline-execution and iOS-evidence validation

**Status:** accepted
**Date:** 2026-08-15

## Context

The second independent review (R2) flagged two acceptance-level gaps:

- **R2-F2 (criterion 3)** — the harness has not been run with actual network
  connectivity removed. The offline guarantee is enforced structurally (CSP
  `connect-src 'none'` plus fail-closed lint on any external script/link/img,
  fetch, XHR, WebSocket, or CSS `url()`/`@import`), but the literal
  disconnected-execution run has not been performed.
- **R2-F5 (criterion 13)** — the iOS status row lacks the identifying evidence
  ADR-0005 itself requires (exact device model, iOS build number, viewer
  version, Files location, transfer method, launch sequence).

Neither is a code defect; both are environment-dependent manual validation.
James decided to defer both at P0.1 rather than block the item.

## Decision

Defer two validations at P0.1, non-blocking:

1. **Actual offline-execution validation** (criterion 3). The deferral does not
   weaken the artifact — the offline guarantee is already enforced at the
   platform level by CSP — it only postpones the demonstrated proof.
2. **iOS status-row identifying evidence** (criterion 13 device/build record).
   The iOS path remains a status row (ADR-0005); the identifying evidence is
   deferred alongside the already-deferred storage-quota work.

Both are marked `[~]` in the roadmap and must be revisited: offline execution
before any later phase introduces a network surface; iOS evidence together with
the storage-quota follow-up in ADR-0005.

## Alternatives considered

| Option | Why not |
|---|---|
| Block P0.1 until offline and iOS evidence are produced | Stalls an otherwise-complete harness on environment-dependent manual checks; neither is a code defect. |
| Mark criteria 3 and 13 met without performing the work | Untruthful. The review protocol forbids claiming a criterion met that was not verified, and ADR-0006 condition 3 forbids silent skips. |

## Consequences

- P0.1 may PASS with criteria 3 and 13 carrying explicit `[~]` deferral markers.
- The deferral is auditable, not silent: the `[~]` markers point here.
- Before any later phase ships a network surface, offline execution must be
  actually demonstrated.

## What would change our mind

A reviewer or James deciding the deferred validation is required for a specific
release — at which point the `[~]` markers are resolved, not deferred.
