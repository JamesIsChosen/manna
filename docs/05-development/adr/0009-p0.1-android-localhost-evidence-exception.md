# ADR-0009 — P0.1 Android localhost execution evidence exception

**Status:** accepted
**Date:** 2026-08-15

## Context

P0.1 criterion 13 requires validation in an Android Chromium-class browser. The exact
P0.1 artifact was executed in an Android 11 emulator (AVD `sdk_gphone_x86_64`, Pixel 5
profile) using Chrome 83.0.4103.106. JavaScript executed, the application rendered,
touch input reached the Reader, and horizontal overflow was absent.

The artifact was pushed to `/sdcard/manna.html`, but Android 11 Chrome denied direct
`file://` access under scoped storage. The same exact artifact was therefore delivered
to the Android browser through:

`adb reverse tcp:8123` → `http://localhost:8123/manna.html`

The normal Manna contract remains stricter: `AGENTS.md` says **No server required**.
The final P0.1 review therefore raised a structural objection: the Android browser was
real, but the origin/transport was server-served localhost rather than direct `file://`.

James, as the human project owner, explicitly chose to accept this evidence for P0.1.

## Decision

For **P0.1 criterion 13 only**, the recorded Android 11 emulator + Chrome 83 execution
over `adb reverse`/localhost is accepted as sufficient Android Chromium-class evidence.

This is an **evidence exception, not a runtime architecture change**. It does not claim
that Android can launch Manna directly from `file://`, and it does not waive Manna's
general no-server/direct-filesystem requirement for release/runtime behavior or later
mobile-platform gates.

## Alternatives considered

| Option | Why not |
|---|---|
| Keep P0.1 blocked until Chrome opens `/sdcard/manna.html` directly | The human owner explicitly accepted the already-demonstrated Android browser execution as sufficient for this feasibility item. |
| Build an Android wrapper or special file-provider path now | That expands P0.1 beyond the smallest feasibility change and would introduce a second execution architecture. |
| Quietly call localhost equivalent to `file://` | Rejected. The transport difference is material and must remain visible in the packet, roadmap, PR, and review history. |

## Consequences

- P0.1 may count the recorded Android emulator/browser run toward criterion 13.
- P0.1 documentation must say that Android used localhost through `adb reverse`.
- Direct Android `file://` launch remains **unproven and unclaimed**.
- `AGENTS.md` remains unchanged: **No server required** is still the general project rule.
- This exception does not automatically carry into P0.8, P0.9, release readiness, or any later acceptance gate.

## What would change our mind

A reproducible direct-filesystem Android launch would replace this weaker evidence with
stronger evidence. Evidence that localhost masked an origin-specific defect would require
the Android feasibility conclusion to be revisited before a later mobile gate can pass.
