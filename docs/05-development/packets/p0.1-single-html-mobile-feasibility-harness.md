## 1. Summary

Implements roadmap item [P0.1 — Single-HTML Mobile Feasibility Harness](../../ROADMAP.md):
a deterministic build that compiles `src/` into one self-contained `dist/manna.html`
(no sibling runtime assets), a central `SelectionService`, a synchronized Study Desk
(Bible, Commentary, Word Study, Atlas, Cross References) with Follow/Pin, a responsive
desk/tablet/phone layout, a Diagnostics screen, and a fail-closed verification suite
including deliberate-failure fixtures. 48/48 tests pass — including a real-browser
smoke test that boots `dist/manna.html` in headless Chromium and asserts `#app`
renders, and a reachability check that no button is clipped or nav-overlapped —
plus `lint` and `build` are green.

## 2. Scope

**In scope:** deterministic build + lint + test harness; the single-file release
artifact; the Matthew 4:12–17 KJV-PCE fixture with Strong's-linked words and place
entities; the central `SelectionService` (verse/word/place); the Study Desk panes with
Follow/Pin; responsive tiers; the Diagnostics screen with build metadata; CSP; the
automated verification suite including negative tests and the reproducibility probe.

**Not in scope** (per the packet §29 and the design "Scope warning"): real SWORD/OSIS
import, IndexedDB persistence, production backup, notes, real Strong's datasets, Bible
search, Verse Finder, morphology, real atlas data, the layout model (resize/reorder/
swap/presets/save), layout persistence, the full 66-book picker, all six themes, and
full-screen/Page-vs-Scroll reading. These are later packets.

**Dead code removed:** two source files carried no caller and were not part of the
build — `src/fixtures/matthew-4.js` (an earlier token-stream fixture representation,
superseded by `src/fixtures/verses.js`) and `src/selection/follow-pin.js` (an earlier
pin helper, superseded by the pin logic in `src/app/state.js`). Neither was in
`scripts/build.js` `JS_FILES`, required by tests, or imported by any bundled module.
Removed in this PR; the artifact SHA-256 is unchanged, confirming they were never build
inputs.

**Review fixes (this revision):** the independent review of this packet found six
findings (F1–F6). The four code findings are addressed here:

- **F1** — `createState(service)` now subscribes to the service, so `service.emit(ctx)`
  drives the same dispatch as `state.emit(ctx)`; a regression test
  (`state: service.emit drives the same dispatch as state.emit (§17)`) exercises the
  production path that the earlier tests had bypassed.
- **F3** — the two selection failure fixtures now fail closed through a child-process
  exit, not an in-process `problems[]` array: `scripts/probe-selection.js --sabotage
  <mode>` exits non-zero when a break is injected (clean run exits 0).
- **F4** — `src/index.html`, `src/ui/styles.css`, `src/ui/icons.svg` are added to the
  build-input set, so the buildId changes when the artifact does.
- **F5** — the Diagnostics field is relabelled `SHA-256 (DIGEST FIELD BLANKED)` and the
  note points at the true final-byte digest in `BUILD-MANIFEST.json` / `manna.html.sha256`.

F2 (manual device/platform matrix, §11) and F6 (reviewer environment) are not code
findings and are tracked separately.

**Navigation-overlap defect (found after the FAIL, fixed here):** desktop Firefox and
Edge showed the reader's `◀ PREV VERSE` / `NEXT VERSE ▶` footer buttons unreachable —
`.bottomnav` is `position: fixed` (62px + 3px border = 65px) and pinned over the
reader, which had `padding-bottom: 0`. Two causes, both fixed:

- **The mobile nav leaked onto desktop.** `.bottomnav` had an unguarded `display: flex`
  in the phone-tier block, overriding the `display: none` default and rendering the
  phone nav at every width. Removed; visibility is now governed solely by the media
  queries (top bar on desktop/tablet, bottom nav on phone only).
- **The phone reader lacked clearance.** The `.phone-body .reader` 200px drawer padding
  does not cover the standalone `.reader-screen`, so its footer sat under the nav with
  no scroll room. The phone `.reader` now reserves `calc(65px + env(safe-area-inset-bottom))`.

Added `browser: no button is clipped by the viewport or overlapped by the fixed nav`:
it scrolls to the bottom on desktop and phone and asserts every rendered button's rect
sits inside the viewport and does not overlap the fixed nav — the general form of the
bug. Verified it fails against the pre-fix artifact (`nav-overlap:◀ PREV VERSE`,
`nav-overlap:NEXT VERSE ▶`).

**Entry-point defect (found after the FAIL, fixed here):** James opened
`dist/manna.html` directly in Chromium and it rendered a blank page — `#app` had zero
children. `boot.js` defined `Manna.app.boot` but nothing invoked it: the bundle had
every module defined and no entry-point call, so the page never rendered despite
`MANNA_META` and the `Manna` globals being present. The entire 46-test Node suite
passed against an artifact that did not run, because no test executed the inlined
`<script>` in a browser engine. Fixed by invoking boot on DOM-ready at the end of
`boot.js` (the bundle's final module). Added `test/browser.test.js`, which builds the
artifact, boots it in a headless Chromium-family browser over the DevTools Protocol
(Edge/Chrome/Chromium, zero npm dependencies), and asserts `#app` has rendered
children and the fixture verses are present in the live DOM. This closes the structural
gap: only a real browser engine can catch a non-rendering artifact.

## 5. Test evidence

New tests (48, all passing), grouped by layer:

- **Browser smoke** (`test/browser.test.js`): builds the artifact, boots it in a
  headless Chromium-family browser over CDP, and asserts `#app` has rendered children
  and the fixture verses (16 and 17) plus study-word token buttons are present in the
  live DOM. This is the check that catches a non-rendering artifact; the Node suite
  cannot.
- **Browser reachability** (`test/browser.test.js`): on desktop and phone, scrolls to
  the bottom and asserts every rendered button's bounding rect sits inside the viewport
  and is not overlapped by the fixed nav. Catches the reader-footer-unreachable bug in
  its general form.
- **Build/artifact** (`test/build.test.js`): produces the three dist files; single-file
  no-sibling-refs; no network references + CSP guard; no absolute paths; all six verses +
  tagged tokens + supplied-word range + WoC marker embedded; required UI markers present;
  manifest↔artifact consistency; self-referential `sha256Embedded` blanking rule;
  lint passes end-to-end; determinism (two byte-identical builds); reproducibility from a
  second source directory.
- **Failure fixtures** (`test/failure.test.js`): each of external JS, external CSS,
  HTTP-fetched fixture, missing artifact, broken selection propagation, and a pinned pane
  that follows is injected and asserted to fail closed with a non-zero exit.
- **Fixture integrity** (`test/render.test.js`): every verse reconstructs the recorded
  PCE source byte-for-byte; token offsets slice to the tagged surfaces; supplied-word
  ranges mark only `by`; no overlapping marks; only word/place tokens; WoC metadata on
  v17 only.
- **Render models** (`test/render.test.js`): `verseParts` marks supplied words and tokens
  and joins back to exact text; commentary/xref/word/atlas models produce the expected
  content; `fmtRef` formats single verses and ranges.
- **Selection/state** (`test/selection.test.js`): subscribe/unsubscribe; full §2 context
  shape; capability matching (§16); context preservation (§14); pin/follow/stale/unpin
  (§39); no redundant re-notify (§22); no context mutation; `onChange` on emit/pin/unpin;
  pin snapshots the displayed context; every pane declares its accepted types.

**Could not verify (manual, recorded in §11):** desktop Firefox and Android

## 6. Assumptions made

- The fixture contract objects (`COM`, `XREF`, `WORDS`, `PLACES`, `DOTS`) are taken from
  `docs/01-spec/design-reference/Study Desk.dc.html`. `PEOPLE`/`TOPICS`/`NOTES` are
  omitted because P0.1 (§51) defines no pane for them.
- Supplied words are represented as `{start,end}` ranges in the fixture model and
  rendered `<i>` (italic) — the print convention — while the source form brackets them,
  so the data model round-trips the module byte-for-byte.
- The self-referential artifact SHA-256 is handled by blanking the digest field before
  hashing (`sha256Embedded`) and recording the true digest (`sha256`) in the manifest.
- CSP `script-src 'unsafe-inline'` and `style-src 'unsafe-inline'` are accepted for P0.1
  because the artifact is self-contained; tightening is deferred to later security packets.

## 10. Security impact

- No network boundary changes: the artifact cannot fetch (CSP `connect-src 'none'`,
  `default-src 'none'`), and lint fails closed on any external script/link/img, fetch,
  XHR, WebSocket, or CSS `url()`/`@import`.
- The only runtime storage touch is a write-then-remove `localStorage` capability probe
  in `diagnostics.js`; P0.1 persists nothing.
- Imported-module threat model is out of scope (P0.1 ships no imports).
