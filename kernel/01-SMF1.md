# SMF/1 — Strict Markdown Front Matter

Machine-bearing Markdown begins with an exact `---\n`, followed by one strict JSON object, followed by exact `---\n`.

## Byte rules

- UTF-8 only; malformed UTF-8 rejected.
- No BOM.
- LF line endings.
- Top-level structured value is exactly one JSON object.
- Duplicate keys rejected.
- YAML-only features do not exist: anchors, aliases, merge keys, tags, comments, implicit dates/booleans.

## Unicode rules

Structured strings are Unicode scalar-value sequences.

- unpaired high-surrogate escape: REJECT
- unpaired low-surrogate escape: REJECT
- valid surrogate pair: decode to one scalar value
- malformed UTF-8: REJECT

Machine identifiers use ASCII grammar defined by SMF-SCHEMA/1 and therefore require no Unicode normalization.

## Numeric rules

Machine-critical JSON integer tokens are allowed only as canonical base-10 integers in the exact range:

`-9007199254740991 ... +9007199254740991`

Rules:

- no `+`
- no leading zero except `0`
- `-0` forbidden
- no decimal point
- no exponent

Wider integers and exact decimal/fixed-point values are schema-defined canonical strings.

## Body semantics

The Markdown body is explanatory/procedural. It cannot add or expand machine authority. Machine evaluation uses the structured SMF surface.

A prose/structured inconsistency is a review/documentation finding, not a parser-dependent authority rule.

## Determinism

Exact record bytes must produce one identical structured AST across conforming implementations or be rejected.
